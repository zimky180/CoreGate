# 核心门控（大核封锁 · 游戏自动恢复）

> KernelSU 模块：**日常使用完全封锁高频大核省电，打开游戏（命中目标包名）自动恢复全部核心**
> 作者：**zimky** · 模块 id：`CoreGate`

专为一加 Ace 6T（骁龙 8 Gen 5，2 超大核 + 6 大核全大核设计）设计，同时**通用适配**任何可热插拔 CPU 的机型（自动检测最高频簇，也可手动指定核心）。

## 原理

- 日常使用：向 `/sys/devices/system/cpu/cpuN/online` 写入 0，把**最高频簇**（如 8 Gen 5 的 2 颗 3.8GHz Oryon 超大核）完全离线。核心离线后彻底不再唤醒，省下 cluster 空闲功耗与频繁迁移的唤醒开销。
- 打开游戏：轮询 `dumpsys activity activities` 获取前台包名，命中游戏列表后把全部核心写回 1，恢复满血；同时可选把在线核心最低频率提升（游戏增强）。
- 离开游戏：自动重新封锁。
- 每轮循环都会重新压制（对抗厂商 core_ctl / 温控把核拉回来的情况），并先关闭高通 `core_ctl`。
- 可选「日常限频」（高级省电，**默认关闭**）：把在线核心的最高频率限制到**固定绝对上限**——小核簇 ≤ 2266 MHz、大核簇 ≤ 1651 MHz、GPU ≤ 500 MHz（功耗档 13）；进游戏自动解除。采用**固定阈值**而非百分比，更贴合 8 Gen 5 的实际频率档位，避免在不同机型上比例失真。仅当当前频率**偏离目标时才写入**，减少与厂商调度反复拉扯与无效写入。
- **默认只操作 CPU**：限频关闭时**完全不碰 GPU**（8 Gen 5 的 GPU 频率/温控逻辑交给厂商方案）；仅当**开启「日常限频」时**才会一并限制 GPU，并在进游戏/恢复/卸载时完整还原 GPU 频率与功耗档位。

## 耗电开销（本模块自身）

- 常驻进程：**仅 1 个 shell 进程**（ksud 启动的 service.sh），`sleep` 期间完全休眠。
- 亮屏时每 3 秒做一次轻量 `dumpsys activity` 前台检测（约几十毫秒）；**息屏自动降频为每 15 秒一次**，屏幕状态用免费 sysfs 读取。
- 每轮只读一个小配置文件 + 免费 sysfs，不做任何 App 进程注入、无 Zygisk、无 native 守护进程。
- 对比：2 颗 3.8GHz 超大核完全离线省下的 idle/唤醒功耗，远大于上述轮询开销。

## 安装

1. 下载 GitHub Releases 附件 `CoreGate.zip`（GitHub 附件名仅支持英文；模块名/界面均为「核心门控」）→ KernelSU 管理器 → 模块 → 本地安装
2. 重启
3. KernelSU 管理器 → 模块 → 打开 CoreGate 的 WebUI
4. 添加你的游戏包名 → 保存（约 2 秒内自动生效，无需重启）

## WebUI 配置项

| 配置 | 说明 | 默认 |
|------|------|------|

| 充电时不封锁 | 插电保持全核在线 | 关 |
| 日常限频 | 🔽 折叠开关（**默认关**）：开启后把在线核心限到固定上限（小核 ≤2266 / 大核 ≤1651 / GPU ≤500 MHz·档13），进游戏自动解除 | 关 |

## 卸载

KernelSU 管理器卸载即可：`uninstall.sh` 会恢复全部核心、**还原 GPU 频率与功耗档位**，并清理配置目录与日志。

## 手动测试（诊断）

WebUI 提供「立即封锁 / 立即恢复」按钮，可验证你的内核是否允许离线核心：
- 若封锁失败，日志会记录 `封锁 cpuN 失败`，常见原因：
  - 内核禁止热插拔（`online` 节点返回 `Device or resource busy` / `Invalid argument`）
  - SELinux 拦截（本模块带 `sepolicy.rule`，一般可解；若你的 KernelSU 对规则报错可删除该文件）
  - 厂商温控/core_ctl 实时拉回（本模块每轮循环自动压制）

## 注意事项 / 免责声明

- 封锁核心属于低风险但非零风险操作：**请先在 WebUI 用「立即封锁」测试**，确认日常流畅后再长期使用。
- 若卡顿/异常：重启即可恢复全部核心（内核默认全核在线）。
- 不建议封锁超过最高频簇（8 Gen 5 建议只封锁 cpu6/cpu7，保留 6 颗大核日常绰绰有余）。
- 游戏检测：`dumpsys window` 抓取 mCurrentFocus / mFocusedApp / mHoldScreenWindow / mTopFullscreenOpaque 四个字段（解决 ColorOS 全屏游戏前台显示为桌面的误判），多候选任一命中即解锁；内置 153 个热门游戏包名，可随时在 WebUI 增删。
- **默认只操作 CPU，不碰厂商云控节点**：限频关闭时完全不碰 GPU；开启「日常限频」后会一并限制 GPU 频率与功耗档位，并在进游戏/恢复/卸载时完整还原（GPU 频率/云控逻辑仍交给厂商自己的方案，不做对抗）。

## 完全可逆 / 零残留保证

- **所有运行时改动都是 sysfs 内核易失状态**（CPU 离线、限频、core_ctl）→ 即使什么都不做，**重启 100% 恢复原始状态**。
- **KernelSU 管理器卸载时**（无需重启）：
  1. 向 service.sh 发送终止信号，进程退出前自动恢复核心/频率/core_ctl 原始值
  2. 全部核心上线、`scaling_max_freq`/`scaling_min_freq` 恢复 cpuinfo 原始值、`core_ctl` 精确还原为首次关闭前备份的原始值
  3. 删除 `/data/adb/CoreGate/`（config.json、日志、状态、PID、备份文件）——模块目录由 KernelSU 移除
- **手动删模块文件夹 / 禁用模块**：服务进程每轮自检，发现模块目录消失立即恢复并退出，不留运行残留。
- 不注入任何 App 进程、不改 system 分区、无 Zygisk、无 native 守护进程 → 系统零残留。

## 防卡机 / 崩溃保护（v1.2.4+）

- **开机延迟锁核**：service.sh 先等 `sys.boot_completed=1`（最多 90 秒）+ 额外 5 秒，系统完全就绪后才首次封锁大核。
- **默认只锁 1 个核（最稳）**：auto 模式默认只封锁最高频簇 1 个核（对应 Scene 实测可行的量，8 Gen 5 = cpu7），也可在 WebUI 手动填 `6 7`（**空格隔开**）。**请先以 1 个核长期使用确认稳定后，再逐步尝试 2 个。**
- **逐核渐进封锁**：每个核离线后间隔 1 秒，避免同时离线多核的冲击。
- **放弃对抗机制**：某核被系统拉回 3 次即放弃封锁该核并记日志，绝不与 ColorOS 调度死磕。
- **core_ctl 默认不碰**（WebUI 开关，默认关）：避免干扰厂商调度；若核总被拉回再开启。
- **崩溃自愈安全模式**：锁核前预置崩溃标记，若进程异常退出（系统崩溃/强杀），下次开机自动进入「安全模式」（不锁任何核），重启一次后自动恢复。避免一锁就卡死、卡死又锁的恶性循环。
- **如果已经卡机/无法进系统**：
  1. 长按电源 10 秒强制重启，多等几分钟（ColorOS 一般会恢复）；
  2. 能进系统 → KernelSU 管理器卸载/禁用本模块，或 WebUI「删除全部残留」；
  3. 进不去 → 若开了 USB 调试且 adbd 可用：`adb shell rm -rf /data/adb/modules/CoreGate`；
  4. 有 TWRP 的话：文件管理删除 `/data/adb/modules/CoreGate` 目录；
  5. 重启后所有核心自动恢复（sysfs 易失状态），模块不加载即一切正常。

## WebUI 核心面板

- **实时核心可视化**：每颗核显示在线/封锁状态 + 当前频率。
- **点击卡片即可封锁/恢复该核**（立即生效并写入配置，cpu0 系统保留不可点）；封锁时自动检查安全阈值，在线核心不足会被拒绝。
- 使用面板开关定制后，「封锁核心」自动转为手动列表（如 `6 7`，空格隔开）；想回到自动模式，把输入框改回 `auto` 保存即可。

- **立即恢复原始状态**：全核上线 + 频率还原（服务继续运行，会按配置重新封锁）。
- **删除全部残留**：恢复核心/频率/core_ctl → 停止模块服务 → 删除 `/data/adb/CoreGate/` 全部数据（配置/日志/状态/PID/备份）。之后模块停止工作；如需继续使用，**重启后自动用模块自带默认配置重新生成**。
- 若在 WebUI 清理后决定彻底弃用：正常卸载模块即可，卸载脚本会再次确保零残留。
