## 原理

- 日常使用：向 `/sys/devices/system/cpu/cpuN/online` 写入 0，把**最高频簇**（如 8 Gen 5 的 2 颗 3.8GHz Oryon 超大核）完全离线。核心离线后彻底不再唤醒，省下 cluster 空闲功耗与频繁迁移的唤醒开销。
- 打开游戏：轮询 `dumpsys activity activities` 获取前台包名，命中游戏列表后把全部核心写回 1，恢复满血；同时可选把在线核心最低频率提升（游戏增强）。
- 离开游戏：自动重新封锁。
- 每轮循环都会重新压制（对抗厂商 core_ctl / 温控把核拉回来的情况），并先关闭高通 `core_ctl`。
- 可选「日常限频」（高级省电，**默认关闭**）：把在线核心的最高频率限制到**固定绝对上限**——小核簇 ≤ 2266 MHz、大核簇 ≤ 1651 MHz、GPU ≤ 500 MHz（功耗档 13）；进游戏自动解除。采用**固定阈值**而非百分比，更贴合 8 Gen 5 的实际频率档位，避免在不同机型上比例失真。仅当当前频率**偏离目标时才写入**，减少与厂商调度反复拉扯与无效写入。
- **默认只操作 CPU**：限频关闭时**完全不碰 GPU**（8 Gen 5 的 GPU 频率/温控逻辑交给厂商方案）；仅当**开启「日常限频」时**才会一并限制 GPU，并在进游戏/恢复/卸载时完整还原 GPU 频率与功耗档位。

## 耗电开销（本模块自身）

- 常驻进程：**仅 1 个 shell 进程**（ksud 启动的 service.sh），`sleep` 期间完全休眠。
- 亮屏时按「检测间隔」轮询前台应用（轻量 `dumpsys` 前台检测，约几十毫秒）；**息屏自动停止前台检测**（纯省电，仅维持封锁），屏幕状态用免费 sysfs 读取。
- 每轮只读一个小配置文件 + 免费 sysfs，不做任何 App 进程注入、无 Zygisk、无 native 守护进程。
- 对比：2 颗 3.8GHz 超大核完全离线省下的 idle/唤醒功耗，远大于上述轮询开销。

KernelSU 管理器卸载即可：`uninstall.sh` 会

1. 恢复全部核心、**解锁并还原 GPU 频率与功耗档位**（限频时 kgsl 节点被 `chmod 444` 锁定，脚本会先解锁再写回）

**全部无需重启。** APK 是独立应用，**卸载模块不会删除 App**（想卸载 App 请去系统「应用管理」正常卸载）；模块也从未写入任何系统分区，卸载即彻底干净。

## 手动测试（诊断）

原生 App「锁核状态」页提供「立即封锁 / 立即恢复」按钮，可验证你的内核是否允许离线核心：
- 若封锁失败，日志会记录 `封锁 cpuN 失败`，常见原因：
  - 内核禁止热插拔（`online` 节点返回 `Device or resource busy` / `Invalid argument`）
  - SELinux 拦截（本模块带 `sepolicy.rule`，一般可解；若你的 KernelSU 对规则报错可删除该文件）
  - 厂商温控/core_ctl 实时拉回（本模块每轮循环自动压制）

## 注意事项 / 免责声明

- 封锁核心属于低风险但非零风险操作：**请先在 App 的「锁核状态」页用「立即封锁」测试**，确认日常流畅后再长期使用。
- 若卡顿/异常：重启即可恢复全部核心（内核默认全核在线）。
- 不建议封锁超过最高频簇（8 Gen 5 建议只封锁 cpu6/cpu7，保留 6 颗大核日常绰绰有余）。
- 游戏检测：多路回退抓取前台包名——优先 `dumpsys window` 的 7 个字段（mCurrentFocus / mFocusedApp / mHoldScreenWindow / mTopFullscreenOpaque / mObscuringWindow / mLastFocusedWindow / mFocusedWindow），未命中再查 activity 栈的 `ResumedActivity`（ColorOS 最可靠），最后用焦点字段兜底；多候选任一命中即解锁。内置 153 个热门游戏包名，可随时在 App 的「策略」页增删。
- **默认只操作 CPU，不碰厂商云控节点**：限频关闭时完全不碰 GPU；开启「日常限频」后会一并限制 GPU 频率与功耗档位，并在进游戏/恢复/卸载时完整还原（GPU 频率/云控逻辑仍交给厂商自己的方案，不做对抗）。

## 完全可逆 / 零残留保证

- **所有运行时改动都是 sysfs 内核易失状态**（CPU 离线、限频、core_ctl）→ 即使什么都不做，**重启 100% 恢复原始状态**。
- **KernelSU 管理器卸载时**（无需重启）：
  1. 向 service.sh 发送终止信号，进程退出前自动恢复核心/频率/core_ctl 原始值
  2. 全部核心上线、`scaling_max_freq`/`scaling_min_freq` 恢复 cpuinfo 原始值、`core_ctl` 精确还原为首次关闭前备份的原始值
  3. **解锁并还原 GPU 节点**（先 `chmod 644` 解除限频时的 `chmod 444` 锁定，再写回原始频率与功耗档位）
  4. **不再清理任何应用**（v2.1.0 起 APK 为独立应用，与模块解耦，卸载模块不影响 App；如需卸载 App，请到系统「应用管理」正常操作）
  5. 删除 `/data/adb/CoreGate/`（config.json、日志、状态、PID、备份文件）——模块目录由 KernelSU 移除
- **手动删模块文件夹 / 禁用模块**：服务进程每轮自检，发现模块目录消失立即恢复并退出，不留运行残留。
- **不改动任何系统分区**（`/system`、`/vendor` 全部不碰，模块 zip 内没有 `system/` 目录树）、不注入任何 App 进程、无 Zygisk、无 native 守护进程 → 系统零残留，卸载即彻底干净。

## 防卡机 / 崩溃保护（v1.2.4+）

- **开机延迟锁核**：service.sh 先等 `sys.boot_completed=1`（最多 90 秒）+ 额外 5 秒，系统完全就绪后才首次封锁大核。
- **默认只锁 1 个核（最稳）**：auto 模式默认只封锁最高频簇 1 个核（对应 Scene 实测可行的量，8 Gen 5 = cpu7），也可在 App 内手动填 `6 7`（**空格隔开**）。**请先以 1 个核长期使用确认稳定后，再逐步尝试 2 个。**
- **逐核渐进封锁**：每个核离线后间隔 1 秒，避免同时离线多核的冲击。
- **放弃对抗机制**：某核被系统拉回 3 次即放弃封锁该核并记日志，绝不与 ColorOS 调度死磕。
- **core_ctl 默认不碰**（App 设置页开关，默认关）：避免干扰厂商调度；若核总被拉回再开启。
- **崩溃自愈安全模式**：锁核前预置崩溃标记，若进程异常退出（系统崩溃/强杀），下次开机自动进入「安全模式」（不锁任何核），重启一次后自动恢复。避免一锁就卡死、卡死又锁的恶性循环。
- **如果已经卡机/无法进系统**：
  1. 长按电源 10 秒强制重启，多等几分钟（ColorOS 一般会恢复）；
  2. 能进系统 → KernelSU 管理器卸载/禁用本模块，或 App 设置页「删除全部残留」；
  3. 进不去 → 若开了 USB 调试且 adbd 可用：`adb shell rm -rf /data/adb/modules/CoreGate`；
  4. 有 TWRP 的话：文件管理删除 `/data/adb/modules/CoreGate` 目录；
  5. 重启后所有核心自动恢复（sysfs 易失状态），模块不加载即一切正常。

## 原生 App 界面（v2.1.0+）

App 采用底部四页导航，对齐 KernelSU / LSPosed 的操作习惯：

| 页 | 名称 | 内容 |
|----|------|------|
| 1 | 锁核状态 | 运行状态、每颗核在线/封锁状态 + 当前频率、锁核建议、一键封锁 / 恢复 |
| 2 | 策略 | 录屏 / 相机自动恢复开关及相关策略 |
| 3 | 日常限频 | 限频开关 + 限频实况（当前小核/大核/GPU 频率） |
| 4 | 自定义 | 主开关、游戏包名列表、匹配方式、息屏策略、充电不封锁、检测间隔、限频自定义，以及诊断 / 测试 / 清理等调试项 |

- **实时核心可视化**：每颗核显示在线/封锁状态 + 当前频率。
- **点击卡片即可封锁/恢复该核**（立即生效并写入配置，cpu0 系统保留不可点）；封锁时自动检查安全阈值，在线核心不足会被拒绝。
- 外观：API 31+ 上使用真·原生 `RenderEffect` 模糊，呈现悬浮玻璃质感。
- 使用面板开关定制后，「封锁核心」自动转为手动列表（如 `6 7`，空格隔开）；想回到自动模式，把输入框改回 `auto` 保存即可。

- **立即恢复原始状态**：全核上线 + 频率还原（服务继续运行，会按配置重新封锁）。
- **删除全部残留**：恢复核心/频率/core_ctl → 停止模块服务 → 删除 `/data/adb/CoreGate/` 全部数据（配置/日志/状态/PID/备份）。之后模块停止工作；如需继续使用，**重启后自动用模块自带默认配置重新生成**。
- 若在 App 里清理后决定彻底弃用：正常卸载模块即可，卸载脚本会再次确保零残留。

### 温度策略（当前实现）

策略页支持高温锁核或高温解封，默认关闭，触发阈值可设为 35～60℃（默认 40℃）。界面显示和策略判断统一使用 Android 电池温度，优先读取 battery/temp，失败时回退到 dumpsys battery；不再读取 CPU / SoC 热点最高温度。不同工具的采样源和刷新时间可能造成读数差异，Scene 的具体采样源尚未核实。

高温锁核在日常封锁名单上叠加独立的「高温额外锁核」名单，可在策略页逐核选择并保存。CPU0 不可选，额外名单默认留空；重复选择日常已经封锁的核心不会增加封锁数量。降至阈值以下 3℃时撤销额外封锁并恢复当前日常名单，不清除用户的手动核心设置。识别到游戏名单中的前台游戏时，跳过高温锁核并恢复全部核心；开启的录屏/相机恢复与充电恢复同样优先。游戏须加入名单且被正确识别，判断按用户设置的轮询间隔执行。

高温解封仍在达到阈值时恢复全部核心并撤销 CoreGate 限频，不保证降低温度。总开关与安全模式始终优先，读取不到有效电池温度时回到普通场景策略。配置由模块守护进程执行，关闭 App 后仍生效；系统自身温控继续生效。

温度检测遵循轮询间隔。需要同时更新 APK 和模块，关闭 App 不影响模块执行。配置字段为 `temperature_enabled`、`temperature_mode`（`lock` / `unlock`）、`temperature_threshold`（摄氏度整数）；旧配置缺键时保持关闭。
